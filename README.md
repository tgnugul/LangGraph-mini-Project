# 콜드스타트 대응 지식 기반 추천 챗봇 (LangGraph + LLM)

> 사용자 행동 로그가 없는 **콜드스타트 상황**에서, 자연어 질의를
> LLM이 SQL로 변환해 추천하는 시스템을 설계·구현한 2인 팀 프로젝트입니다.
> 협업 필터링 대신, 명시적 제약을 지식(규칙)으로 다루는 접근을 택했습니다.
> *(연구 설계와 구현까지 진행 · 성능 고도화는 미완)*

## 문제: 데이터는 있는데, 추천할 수가 없었다

제주 관광 공공데이터(가맹점·월별/요일별 방문 통계 등)를 받았지만, 그 자체로는
"이 사용자에게 무엇을 추천할지"를 알 수 없었습니다. 사용자의 과거 행동 기록이 없는
**콜드스타트** 상황이었기 때문입니다. 행동 로그를 학습하는 협업 필터링은 쓸 수 없었습니다.

그래서 저는 접근을 바꿨습니다. **데이터를 학습하는 대신, 지식(규칙·제약)으로 추천하자.**
사용자가 자연어로 준 조건(지역·시간·선호 등)을 명시적 제약으로 받아, 이를 SQL로 변환해
조건을 충족하는 결과를 반환하는 **지식 기반 추천(Knowledge-based Recommendation)** 구조입니다.
행동 데이터가 없어도 동작하므로 콜드스타트에 강합니다.

## 나의 설계: 추천 전략과 에이전트 흐름

정형화된 rule-based 시스템은 정해진 입력에만 반응하고, 조건이 없으면 대응하지 못합니다.
저는 LLM과 에이전트(LangGraph)를 결합해, 질문의 맥락과 조건 유무를 판단하고
상황에 맞는 추천 전략을 고르는 흐름을 설계했습니다.

```
자연어 질의
   │
   ▼
[의도·조건 파악]  ── 조건(지역·시간·선호)이 있는가?
   │
   ▼
[추천 전략 분기]  ── 인기 기반 / 거리 기반 / 유사도 기반
   │
   ▼
[제약 → SQL 변환]  ── 전략에 따라 반영할 제약이 달라짐
   │
   ▼
[SQL 실행 → 결과 → 자연어 응답]
```

**전략별로 제약을 다르게 다루는 규칙**을 직접 정의했습니다. 예를 들어:
- 시간대 정보가 없으면 시간대 컬럼을 쓰지 않고, 최근 2~3개월 평균으로 대체
- 성별·연령대 조건이 있으면 대응 컬럼을 반드시 포함
- "7월" 같은 표현을 정확한 월별 컬럼명으로 강제 매핑

즉, 추천 전략(인기/거리/유사도)에 따라 **어떤 제약을 어떻게 SQL에 반영할지가 달라지도록**
설계한 것이 이 프로젝트의 핵심입니다.

## 직접 부딪히며 배운 것

- **LangGraph 초창기에 맨몸으로**: 당시 LangGraph가 막 쓰이기 시작한 때라 참고할 자료가 적었습니다. State 정의, 노드 간 데이터 형식·전달 과정에서 나는 에러들을 하나하나 해결하며, 에이전트 워크플로우를 구성하는 법을 스스로 익혔습니다. 이 경험은 이후 다른 프로젝트에서 에이전트를 설계하는 밑바탕이 되었습니다.
- **원본 데이터를 직접 파고들기**: 주어진 데이터만으로는 추천이 불가능했기에, 여러 데이터 파일을 살펴보며 어떤 컬럼을 쓸 수 있고 무엇과 무엇을 연결하면 의미 있는 결론이 나오는지 분석했습니다.
- **프롬프트의 한계를 몸으로**: 당시 유행하던 프롬프트 엔지니어링으로 문제를 풀려 많은 노력을 기울였는데, 그 경험이 오히려 **"프롬프트로 풀 문제와 학습(파인튜닝)으로 풀 문제는 다르다"**는 것을 구분하는 눈이 되었습니다. 이 깨달음이 이후 파인튜닝 연구로 이어졌습니다.

- 정량적 성능 평가 체계를 완성하지 못한 채 마무리되어, 성능 고도화는 과제로 남았습니다.

이 프로젝트는 제가 처음으로 제대로 설계부터 구현까지 이끌어 본 프로젝트로,
완성도보다 **문제를 정의하고 접근을 설계하며 스스로 배운 과정**에 의미가 있습니다.
